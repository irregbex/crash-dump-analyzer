CRASH DUMP ANALYZER 1.6.0 - CÓDIGO FUENTE
=========================================
En el repositorio de GitHub las pruebas se ejecutan desde la raíz:
  node tests/core_test.js CrashDumpAnalyzer.html [carpeta con .dmp opcional]
  python tests/make_pe_ref.py modulo_x64.dll > pe_ref.json
  node tests/pe_unwind_test.js CrashDumpAnalyzer.html modulo_x64.dll pe_ref.json

El código fuente es el mismo CrashDumpAnalyzer.html de la carpeta superior.
No hay compilación ni minificación.

Pruebas
-------
1) node tests\core_test.js ..\CrashDumpAnalyzer.html "<carpeta con .dmp>"
   - Imprime por cada dump: culpable, confianza, instrucción decodificada
     y advertencias del parser.
   - Después verifica:
       * notas: exportar y volver a importar, rechazo de un archivo
         inválido, notas incluidas en el informe;
       * columnas del CSV y cantidad de dumps del JSON;
       * anonimizado sobre rutas sintéticas;
       * paridad de claves I18N.
2) python tests\make_pe_ref.py <modulo_x64.dll> > pe_ref.json
   node tests\pe_unwind_test.js ..\CrashDumpAnalyzer.html <modulo_x64.dll> pe_ref.json
   - Compara parsePE con pefile (timestamp, SizeOfImage, exports y .pdata).
   - Para cada función sin registro de frame ni cadena, arma un stack
     sintético con el tamaño de frame calculado por pefile.
   - Verifica que unwindX64 recupere la dirección de retorno y el RSP
     exactos.

3) Chromium headless (opcional, no incluido en tests\): en 1.5.0 se usó un
   script Playwright que carga la demo, recorre pestañas e idiomas, descarga
   las exportaciones con "Hide memory" activo, mide el contraste del
   selector de notas en tema oscuro y verifica 0 errores JS y 0 peticiones
   de red. La página no permite 'unsafe-eval' (CSP), así que
   page.waitForFunction no sirve: usar bucles con $$eval.

Requisitos: Node 16 o superior; Python 3 con pefile (solo para la prueba 2).
